## 2. Product Goal

Enable **controlled real AI/image provider-backed generation** for the Türkü video workflow while:

1. Keeping deterministic fallback available at all times.
2. Preserving all existing safety gates (human review, copyright review, source confidence).
3. Adding provider-specific safety envelope, sanitization, and audit.
4. Making provider mode explicit, observable, and switchable per-project.
5. Never exposing raw provider payloads, storage keys, credentials, or binary data to the frontend/admin UI.
6. Never auto-approving provider output.
7. Never publishing, exporting, or publicly delivering provider output.

### User Story

> As an admin, I want to switch a Türkü video project from deterministic stub mode to real AI/image provider mode, so that the story, scenario, storyboard, and scene images are generated by a real AI/image service — while retaining full human review control, copyright safety, and the ability to fall back to stubs at any time.

## 3. Provider Enablement Strategy

### Provider Modes (per-project)

| Mode | Description | Behavior |
|------|-------------|----------|
| `DETERMINISTIC_STUB` | Default. No external calls. | FP-019 behavior. Hardcoded safe output. |
| `PROVIDER_DRAFT` | Real provider enabled, output is draft. | Provider called. Output marked as draft. Human review required. |
| `PROVIDER_DISABLED` | Provider explicitly disabled by admin. | Provider not called. Stub output used. |
| `PROVIDER_FAILED_SAFE` | Provider was called but failed. | Safe fallback. Error logged. No retry without admin action. |
| `HUMAN_REVIEW_REQUIRED` | Provider succeeded, awaiting review. | Output available for admin review. Not auto-approved. |

### Mode Transitions

```
DETERMINISTIC_STUB ──(admin enables)──→ PROVIDER_DRAFT
PROVIDER_DRAFT ──(provider success)──→ HUMAN_REVIEW_REQUIRED
PROVIDER_DRAFT ──(provider failure)──→ PROVIDER_FAILED_SAFE
PROVIDER_FAILED_SAFE ──(admin retry)──→ PROVIDER_DRAFT
PROVIDER_FAILED_SAFE ──(admin fallback)──→ DETERMINISTIC_STUB
HUMAN_REVIEW_REQUIRED ──(admin approves)──→ continues pipeline
HUMAN_REVIEW_REQUIRED ──(admin rejects)──→ PROVIDER_DRAFT (retry)
Any ──(admin disables)──→ PROVIDER_DISABLED
PROVIDER_DISABLED ──(admin re-enables)──→ PROVIDER_DRAFT
```

### Design Rationale

- Provider mode is **per-project, per-stage** — admin can enable provider for story but keep stubs for images.
- No global "enable all providers" switch. Each project is explicitly controlled.
- Default is always `DETERMINISTIC_STUB`. Provider enablement is an explicit admin action.
- `PROVIDER_FAILED_SAFE` ensures no silent failure. Admin must acknowledge and decide.

## 5. Safe Output Policy

### 5.1 No Lyrics Dumping

| Rule | Enforcement |
|------|-------------|
| AI prompt MUST NOT request full lyrics reproduction | Prompt template enforced |
| AI output MUST be scanned for lyrics-like patterns | Post-generation sanitizer |
| `lyricsIncluded` flag MUST remain `false` | Safety envelope check |
| LYRICS_NOT_INCLUDED review flag MUST remain present | Pipeline invariant |

### 5.2 Cautious Cultural/Historical Claims

| Rule | Enforcement |
|------|-------------|
| Prompt template instructs AI to use hedging language | Template version control |
| Output scanned for absolute claims | Post-generation sanitizer |
| `CULTURAL_CONTEXT_REVIEW_REQUIRED` flag always present | Pipeline invariant |
| `SOURCE_REVIEW_REQUIRED` when confidence < HIGH | Confidence-based gating |

### 5.3 Source Confidence + Human Review Retained

- `sourceConfidence` always computed. LOW/UNKNOWN triggers extra flags.
- `needsHumanReview` = **always true**. No auto-approval path.
- `copyrightReviewRequired` = **always true**. No automatic clearance.

### 5.4 Provider Output Sanitization

Every provider output MUST pass through `TurkuOutputSanitizer` before storage or response:

1. **Strip raw provider metadata** (request IDs, model versions, token counts).
2. **Strip any embedded URLs** (public, signed, CDN, storage).
3. **Strip any base64/binary content**.
4. **Detect and block lyrics-like content**.
5. **Detect and flag absolute cultural/historical claims**.
6. **Detect and block prompt injection patterns in output**.
7. **Normalize to safe internal representation**.

### 5.5 Prompt-Injection Resistance

| Layer | Protection |
|-------|-----------|
| Input validation | User-supplied text sanitized before prompt construction |
| Prompt template | System prompt instructs model to ignore user-injected instructions |
| Output scanning | Post-generation check for instruction-following artifacts |
| Safety envelope | `promptInjectionChecked = true` required before output accepted |
| Failure mode | `PROMPT_INJECTION_DETECTED` → `PROVIDER_FAILED_SAFE`, admin notified |

## 6. Image Generation Safety

### 6.1 Safe Internal References

| Rule | Enforcement |
|------|-------------|
| Image refs use opaque `internal-ref:{uuid}` format | Service-level enforcement |
| No `https://`, `http://`, `s3://`, `gs://` in refs | Sanitizer + test |
| No base64 or `data:image` in refs | Sanitizer + test |
| No storage keys, bucket names, object paths | Sanitizer + test |
| No raw provider response fields | Sanitizer + test |

### 6.2 Image Storage (Internal Only)

- Provider image output stored internally via opaque reference.
- Admin UI sees only `safeInternalRef` (opaque string).
- No public URL, signed URL, CDN URL, or download link generated.
- No base64/binary sent to frontend. Ever.
- Internal preview uses server-side proxy if needed (future task, not FP-020).

### 6.3 Provider-Specific Image Safety

- Negative prompt includes standard safety constraints (no violence, no explicit, no real persons).
- Provider content policy violations → `PROVIDER_CONTENT_POLICY_VIOLATION` → `PROVIDER_FAILED_SAFE`.
- Image metadata stripped before storage (EXIF, GPS, model metadata).

## 7. Admin Review Gates

### 7.1 No Auto-Approval

| Rule | Enforcement |
|------|-------------|
| `autoApproved` = **always false** in safety envelope | Pipeline invariant |
| No code path sets `autoApproved = true` | Test regression |
| Provider output enters `HUMAN_REVIEW_REQUIRED` mode | State machine |
| Admin must explicitly approve each generation stage | Controller enforcement |

### 7.2 actorRole Remains TEST_FALLBACK

- actorRole is **not** production auth. It is workflow context input.
- All future FP-020 POST actions MUST use `AdminActorResolver` and `AdminActorBoundaryPolicy`.
- SYSTEM actor blocked from normal FP-020 POST endpoints.
- No Spring Security, no JWT, no session, no principal, no Authorization header.

### 7.3 Future POST Actions and Actor Boundary

Every new POST endpoint in FP-020 MUST:
1. Accept `actorRole` + `actorReference` as query params (TEST_FALLBACK).
2. Resolve via `AdminActorResolver`.
3. Enforce via `AdminActorBoundaryPolicy`.
4. Block SYSTEM for non-handoff paths.
5. Return 403 BOUNDARY_POLICY_VIOLATION for violations.

## 11. Observability/Audit Safety

### Generation Audit Trail

Every provider call produces:
1. **TurkuProviderTraceReference** — opaque trace ID, provider alias, timestamp.
2. **TurkuGenerationSafetyEnvelope** — full safety state for that generation.
3. **ai_generation_logs** entry (future DB, currently in-memory) — stage, provider mode, success/failure, sanitization actions.

### Safe Audit Fields

| Included | Excluded |
|----------|----------|
| Opaque trace ID | Raw provider request body |
| Provider alias (e.g. "openai-gpt4") | Raw provider response body |
| Generation stage | API key / credential |
| Success/failure code | Raw endpoint URL |
| Sanitization actions taken | Token counts / billing |
| Review flags | Base64 / binary data |
| Timestamp | Storage keys / paths |

### Observability Contract

- Admin can see: trace ID, provider alias, stage, status, flags, warnings.
- Admin cannot see: raw provider data, credentials, storage internals, billing.
- No audit field exposes production auth, JWT, session, or principal.
